Single Cloudflare Worker entry at `src/index.ts` bootstraps a typed Hono app (`Hono<{ Bindings: Env }>`) that mounts six route modules under `/api/{translate,vocab,review,sessions,tracks,songs}` plus `/api/plan` and `/api/health`, and serves a SPA from `public/`. The `ai/` layer abstracts any OpenAI-compatible chat-completions endpoint (DeepSeek, OpenAI, or generic `openai-compatible`) behind an `AIProvider` interface configured entirely from `wrangler.toml` vars/secrets; routes consume it via `getProvider(env)`. Business logic is split into `services/`: `srs.ts` implements FSRS scheduling with context-linked review cards, streaks, and retention stats (scheduling primitives live in `fsrs.ts` via ts-fsrs); `teach.ts` handles free-form teaching flows; `tracks.ts` seeds the HSK1 curriculum and generates AI track lessons; `songs.ts` glosses pasted song lyrics line-by-line (one AI pass, stored in the `songs` table) and teaches the whole song with a second single AI pass (`POST /api/songs/:id/study`): per-line grammar/notes + song-level character breakdown are stored on `songs.study`, one session per line is upserted (deduped by `input_norm`, so repeated chorus lines share a session), and vocab enters the shared FSRS queue via `session_vocab` links. Individual lines can still be re-taught via the existing `teach()` pipeline (`POST /api/songs/:id/lines/:idx`). `plan.ts` computes the adaptive daily plan; `rate-limit.ts` enforces per-IP limits. Persistence is exclusively through Cloudflare D1 SQLite, with schema in `migrations/` (0001: vocab/sessions/review_log/rate_limits; 0002_sessions_dedup + 0002_memory_and_tracks + 0003: fsrs_state, sessions.kind, input_norm dedup key, tracks/track_items/track_progress; 0004: songs + song_study; 0005: songs.study column for whole-song lessons). Shared types live in `src/types.ts` (Env bindings) and `src/db.ts` (row shapes). Static assets are synced from the sibling web app via `scripts/sync-web.sh` before deployment. Local docs under `docs/` are private and git-ignored.
